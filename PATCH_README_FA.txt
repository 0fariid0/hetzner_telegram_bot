اصلاح تعویض Primary IPv4 — نسخه 16.2
مبنای بررسی: 5ae2afbec760367a336715c847fcd64780ed5985
مخزن: https://github.com/0fariid0/hetzner_telegram_bot

فایل‌های جایگزین:
bot.py
setup.sh
VERSION
تغییر setup.sh فقط هماهنگ‌کردن نسخه Installer با نسخه ربات است.

یافته‌های بررسی کد قبلی:
۱. سرور ابتدا خاموش می‌شد و بعد درخواست ساخت IP جدید ارسال می‌شد؛ خطای سهمیه یا API در این مرحله باعث خاموشی غیرضروری بود.
۲. safe_edit فقط یک نوع خطای تلگرام را مدیریت می‌کرد. خرابی ارتباط تلگرام بعد از خاموشی می‌توانست مسیر روشن‌کردن را قطع کند. حتی خطای نمایش پیام بعد از اتصال IP می‌توانست بازگردانی ناموفق را شروع کند.
۳. old_unassigned فقط پس از موفقیت انتظار Action تغییر می‌کرد؛ اگر درخواست جداسازی اجرا می‌شد ولی پاسخ آن نمی‌رسید، بازگردانی به وضعیت واقعی اتصال IP توجه نمی‌کرد.
۴. بازگردانی قبل از اتصال مجدد IP قبلی، احتمال متصل‌شدن IP جدید را بررسی و مدیریت نمی‌کرد.
۵. برخی خطاهای روشن‌شدن فقط در لاگ ثبت می‌شدند. حتی بعد از نرسیدن سرور به Running، پیام نهایی موفقیت صادر می‌شد.
۶. عملیات نیمه‌تمام بعد از توقف فرایند ربات قابل بازیابی نبود.
۷. جلوگیری از تعویض IP میزبان خود ربات وجود نداشت؛ در این حالت با خاموش‌شدن میزبان، خود ربات هم خاموش می‌شود و قادر به ادامه نیست.

اصلاحات:
- آماده‌سازی IP مقصد قبل از خاموشی.
- جلوگیری از تعویض IP میزبان ربات؛ تشخیص با Metadata هتزنر.
- مستقل‌بودن عملیات سرور از خرابی نمایش پیام تلگرام.
- تأیید نتیجه Action و بررسی مجدد اتصال واقعی IPها.
- تلاش مجدد برای روشن‌شدن؛ اعلام موفقیت فقط پس از تأیید Running.
- در خطا، بررسی عملیات درحال‌اجرای هتزنر و بازگردانی IP قبلی در صورت امکان.
- عدم خاموشی اجباری و عدم حذف خودکار IPها در بازیابی.
- ثبت وضعیت قبل از خاموشی و تلاش برای بازیابی در شروع بعدی ربات.
- حفظ رکورد بازیابی هنگام نامشخص‌بودن نتیجه؛ جلوگیری از تعویض تازه روی همان رکورد.
- حفظ حالت خاموش اولیه در مسیر شکست؛ در مسیر موفق، مطابق رفتار قبلی سرور روشن می‌شود.
- محدودکردن زمان درخواست‌های API به ۳۰ ثانیه.

نصب روی نصب موجود:
ZIP را در پوشه‌ای جدا، مثلاً /root/hetzner-ip-fix استخراج کنید.
از همان پوشه اجرا کنید:

bash setup.sh

گزینه 2 یعنی Update را انتخاب کنید. Installer فایل‌های همین پوشه را نصب می‌کند و تنظیمات قبلی را حفظ می‌کند. ZIP را برای این روش داخل /opt/hetzner-telegram-bot استخراج نکنید؛ Installer در آن مسیر به سراغ نسخه GitHub می‌رود.
این اصلاح به GitHub شما Push نشده است؛ دستور دانلود قبلی تا وقتی فایل‌ها را در مخزن جایگزین نکنید، نسخه قبلی را می‌گیرد.

تنظیم میزبان ربات:
در Hetzner Cloud معمولاً شناسه به‌صورت خودکار از Metadata خوانده می‌شود.
اگر تشخیص خودکار ممکن نبود، در /opt/hetzner-telegram-bot/.env این گزینه را قرار دهید:
BOT_HOST_SERVER_ID=شناسه_عددی_سروری_که_ربات_روی_آن_نصب_است
این شناسه با شناسه سرور مقصد تفاوت دارد؛ مقدار باید میزبان خود ربات باشد.
فقط اگر ربات خارج از Hetzner Cloud اجرا می‌شود:
BOT_HOST_SERVER_ID=0
سپس:
sudo systemctl restart hetznerbot
اگر ربات روی سرور هدف نصب است، برای تعویض IP آن باید ربات روی ماشین دیگری اجرا شود.

بازیابی و لاگ:
رکوردهای عملیات در پوشه .ip-swap-state کنار bot.py ذخیره می‌شوند. IP_SWAP_STATE_DIR مسیر دلخواه را تعیین می‌کند و باید برای کاربر سرویس قابل نوشتن باشد.
توکن در رکورد نوشته نمی‌شود؛ نام فایل به اثرانگشت توکن وابسته است. برای بازیابی همان پروژه و همان توکن قبلی را نگه دارید.
اگر API در دسترس نباشد یا نتیجه خاموشی روشن نباشد، بازیابی تضمین نمی‌شود؛ رکورد نگه داشته می‌شود و پیام خطا داده می‌شود. برای تلاش دوباره، ربات را راه‌اندازی مجدد کنید.
اگر عملیات بیرون از ربات تغییر کرده یا خاموشی رد شده و رکورد همچنان مانده، ابتدا سرور/IPها و Actionهای جاری را در Hetzner بررسی کنید. رکورد را بدون اطمینان از پایان عملیات حذف نکنید.
IP ساخته‌شده و آزاد در مسیر خطا ممکن است باقی بماند و هزینه داشته باشد؛ پس از بررسی، IP آزاد غیرلازم را از بخش Primary IPv4 حذف کنید.
مشاهده لاگ:
sudo journalctl -u hetznerbot -n 150 --no-pager

اعتبارسنجی:
۲۵ تست آفلاین، شامل قطع تلگرام، خطای سهمیه، شکست جداسازی/اتصال، گم‌شدن پاسخ بعد از اجرای درخواست، خطای روشن‌شدن، Timeout، بازگردانی، توقف عملیات، بازیابی پس از restart و جلوگیری از عملیات روی میزبان، موفق شدند.
بررسی py_compile، bash -n و git diff --check موفق بود.
هیچ درخواست تغییردهنده‌ای روی حساب هتزنر یا سرور واقعی شما اجرا نشد.

حدود نتیجه:
این کد در روند تعویض IP وارد Ubuntu نمی‌شود، دیسک را پاک نمی‌کند و Netplan/GRUB را تغییر نمی‌دهد. خاموش‌شدن برای جابه‌جایی Primary IP طبق API هتزنر لازم است.
Running فقط روشن‌بودن ماشین مجازی است؛ بوت کامل Ubuntu یا دسترسی SSH را ثابت نمی‌کند.
رفع این باگ‌ها، تعمیر خودکار سروری که از قبل دچار مشکل بوت/فایل‌سیستم/شبکه بوده نیست. علت دقیق خرابی فعلی بدون لاگ ربات و کنسول همان سرور تأیید نشده است.
